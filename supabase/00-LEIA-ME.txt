SETUP DO BANCO DE DADOS — EI PLACAR
======================================

Rode os arquivos NESSA ORDEM no SQL Editor do Supabase (um de cada vez,
ou todos colados juntos — a ordem numerada já garante que funciona):

1. 01-tabela-jogos.sql       → cria a tabela de jogos
2. 02-tabela-banca.sql       → cria a tabela da banca
3. 03-tabela-escudos.sql     → cria a tabela de escudos dos times
4. 04-tabela-perfis.sql      → cria a tabela de login/perfis + gatilho automático (grava nome,
                                 telefone, data de nascimento e e-mail já na criação da conta)
                                 + todas as colunas extras (assinatura, pagamento, foto etc.)
5. 05-seguranca-rls.sql      → ativa a segurança (só quem logar acessa os dados)
6. 06-tabela-config-app.sql  → cria a tabela de configuração do sistema (preços/planos)
7. 07-jogos-fixture-id.sql   → adiciona a coluna que evita duplicar jogos importados da API-Football
8. 08 a 12                   → ajustes incrementais (nomes de campeonato, país, jogos
                                 agendados, favoritos) — pode rodar todos, são independentes
                                 entre si

13-vincular-banca-antiga-EXECUTAR-UMA-VEZ.sql → NÃO faz parte do setup padrão.
                                 É um script pessoal, com um e-mail específico dentro, pra
                                 migrar a linha antiga e compartilhada da Banca (de antes dela
                                 virar individual) pra uma conta específica. Só roda se você
                                 já vinha usando o sistema antes dessa mudança — quem for
                                 configurar do zero pode ignorar esse arquivo.

14-rate-limiting.sql          → Recomendado, mas OPCIONAL. Cria a tabela que limita quantas
                                 tentativas seguidas de pagamento a mesma pessoa pode fazer
                                 (auditoria de segurança). Sem rodar esse arquivo, o sistema
                                 funciona normal, só sem esse limite extra — pode rodar quando
                                 quiser, não precisa ser antes de mais nada.

IMPORTANTE: o arquivo 05 depende das tabelas dos arquivos 01 a 04 já
existirem — por isso ele tem que rodar depois delas. O 06 pode rodar a
qualquer momento depois do 04 (ele cuida da própria segurança sozinho).

Depois de rodar tudo:
- Vá em Settings → API no Supabase
- Copie a URL do projeto e a chave "anon public"
- Cole essas duas informações na tela ⚙️ Configurar do app

Se você já tinha essas tabelas criadas antes (de uma versão anterior),
pode rodar tudo de novo sem medo — os comandos usam "if not exists" e
"drop ... if exists", então não duplicam nem dão erro. Não precisa
apagar nada manualmente antes: pode simplesmente rodar os arquivos de
novo, na ordem, por cima do que já existir.

Todas as colunas de perfil (telefone, data de nascimento, foto, e-mail,
assinatura, pagamento) e o gatilho de cadastro completo já estão dentro
do 04-tabela-perfis.sql — não tem mais nenhum arquivo separado só pra
isso. Se antes você tinha rodado um "15-pix-idempotencia.sql" ou
"16-cadastro-dados-completos.sql" de uma versão anterior, pode ignorar:
já foi tudo incorporado ao 04. Basta rodar o 04 de novo (por cima) que
fica tudo igual.

SEGURANÇA — depois de rodar tudo, revise o arquivo
"auditoria-seguranca-ei-placar.md" (na raiz do projeto) e, no painel da
Netlify, configure a variável de ambiente MP_WEBHOOK_SECRET (copiar em
Suas integrações → aplicação → Webhooks → Configurar notificações →
"Assinatura secreta", no painel do Mercado Pago) pra ativar a validação
de assinatura do webhook de pagamentos.
